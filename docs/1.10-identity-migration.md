# baseSteam 1.10.2 Identity Migration

Version `2.2.6.110021` is based on Steam Advantage commit
`1b879c4da9f39a87aea17b90dc692356ef288861`. It has not been published.
Automated checks do not replace manual gameplay testing.

## New Identity

| Surface | Value |
| --- | --- |
| Display and artifact name | `baseSteam` |
| Mod and asset namespace | `basesteam` |
| Implementation package | `zone.moddev.mc.basesteam` |
| Version | `2.2.6.110021` |
| Runtime dependencies | `required-after:basepower@[2.4.4.110021,);after:basemetals` |
| CurseForge required relations | `basepower,base-metals` |
| CurseForge project | `0`, unassigned; publication blocked |

The main class keeps its Java name `SteamAdvantage` inside the new package. Build overrides
`powerAdvantageDeobfJar` and `steamAdvantageRunDirectory` retain their existing names so local tooling
can continue to pass them. Local checkout directory names do not determine the artifact identity.

## Saved Data

The shared `zone.moddev.mc.basepower.compat.LegacyIdentity` helper handles missing mappings through
Forge 1.10's `event.getAll()`. Both blocks and items, including block items, are remapped from
`steamadvantage:<path>` to `basesteam:<path>`. Unsupported owned mappings fail instead of being discarded.
Other mods' namespaces are not remapped by Steam's event handler.

All twelve original tile IDs `steamadvantage.<name>` are load alternatives for new canonical IDs
`basesteam.<name>`. Forge's `registerTileEntityWithAlternatives` preserves the canonical write ID.
The tile names are `steam_boiler_coal`, `steam_boiler_electric`, `steam_boiler_geothermal`, `steam_tank`,
`steam_furnace`, `steam_crusher`, `steam_drill`, `steam_elevator`, `drillbit`, `steam_still`, `steam_pump`,
and `steam_boiler_oil`. Existing machine NBT fields, inventories, energy, progress and direction formats
are not changed by this rename.

The original 1.10 source registers no non-tile custom entities. Muskets resolve hits directly through a
ray trace, without spawning a projectile. There is therefore no historical musket projectile save ID to
alias in this target. No new entity or projectile behavior is introduced.

### Deliberate Enchantment Exception

The registry keys `steamadvantage:high_explosive`, `steamadvantage:powderless`,
`steamadvantage:rapid_reload`, and `steamadvantage:recoil` are retained. Registration order and dynamic
numeric allocation are unchanged. Forge 1.10 missing mappings cover only blocks and items;
`PersistentRegistryManager` restores enchantments through its saved registry snapshot. Enchanted item
NBT stores numeric short IDs. Retaining the original keys matches that snapshot; aliases alone would
load the old canonical keys again, and registering a second renamed set is not a safe substitute.
This is a scoped persistence exception under the new `basesteam` mod, not a legacy `ModContainer`.
The regression test checks the actual saved `tag.ench[].id` short, its registry target, and the same
numeric ID after loading and resaving the item.
This rename does not repair pre-existing enchantment-ID differences caused by unrelated mod-list changes.
Custom loot rules referring to these enchantments must retain their old keys.

The public `cyano.poweradvantage.api` package, required `com.mcmoddev` compatibility types, and
external Base Metals and OreSpawn packages remain unchanged. Steam implementation references to
`zone.moddev.mc.poweradvantage` and Power-owned model textures now point to `basepower`.
Unnamespaced steam conduit and damage-source names remain unchanged.

## Configuration And Loot

`steamadvantage.cfg` is copied byte-for-byte to `basesteam.cfg` only when the latter does not exist.
The original is retained and an existing new configuration wins. Fuel-setting values and files are
not rewritten. For the two basePower-owned oils, the boiler checks the raw fluid name first, then the
current `fluid.basepower.crude_oil` or `fluid.basepower.refined_oil` key, then the corresponding old
`fluid.poweradvantage.*` key. Explicit zero values still disable burning. The legacy fallback applies
only to these exact two basePower fluid identities, not foreign fluids or other names.

Before generating loot defaults, the shared helper imports JSON from
`config/additional-loot-tables/steamadvantage` into the corresponding `basesteam` paths. Owned item
identifiers change, custom numbers and foreign namespaces remain, and existing canonical files win.
Original files become `*.json.before-basesteam`, preserving their bytes without leaving two active
`*.json` pools. Missing defaults are created with `CREATE_NEW`; existing migrated or administrator
rules are not overwritten. Migration errors stop initialization and require inspection of the retained
files before retrying. Do not rename inactive backups back to `.json` alongside the new files.

## Build And Test Status

The local JUnit reports contain 135 tests, with no failures, errors or skipped tests. The full
build, dependency, archive, checksum and Eclipse checks also pass with the exact basePower pin.
The main jar remains SHA-256
`728E37A1A0551596D8167976A7022E31EF075A383640BB385470160DD9A8F07D`.

The build pins basePower source commit `425af862ef5b41b61d3e1f7e665d1d691852ff4b` and development-jar
SHA-256 `2992F2CADC30D8F61A17216DF9AB02BDF8E8211BB8B494A6CCED70A3267F69FE` in properties,
the fixed audit, CI and CodeQL. Neither an old Power artifact nor a moving branch is an acceptable substitute.

Added tests cover original tile reads and canonical resaves, the missing-mapping event contract,
numeric enchantment round-trips, hitscan behavior, configuration copying, custom loot import,
inactive backups, existing-new precedence, invalid JSON, and default-file non-overwrite behavior.
Existing regression tests are relocated with their implementation package, without changing their
behavioral assertions or replacing historical fixtures.

The [cross-mod qualification notes](https://github.com/MinecraftModDevelopmentMods/basePower/blob/master-1.10.2/docs/1.10/base-qualification.md)
record the exact-artifact original-world, operating, restart and finite-supply endurance checks.
Those results are separate from hosted CI and manual client acceptance. Generated worlds and raw
reports stay outside source control. Project ID `0` deliberately prevents publication until a new
CurseForge project is assigned; the former Steam Advantage project must not be reused.
